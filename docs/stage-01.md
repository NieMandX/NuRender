# NuRender / Structured Renderer 0.1

Исследовательский прототип: сравнение хранения повторяющейся архитектуры.
Работа ведётся только в этой папке. Предыдущий разговор сохранён в
`structured_renderer_codex_context_recovered.md`.

## Архитектура и критерии эксперимента (до реализации)

- TypeScript, Vite, прямой WebGPU / WGSL. Без движка сцены и нейросетей.
- Общая индексированная геометрия куба: 24 вершины, 36 индексов.
- Процедурный квартал: сцена → здания → общий шаблон фасадов → детали.
- A: шаблон развёрнут на CPU в плоский массив инстансов куба; повторная
  геометрия инстансируется, отдельного draw call на каждое окно нет.
- B: хранит общий шаблон и параметры каждого здания. Vertex shader
  вычисляет buildingId и localPartId из instance_index и применяет
  локальное преобразование. Это параметрическое хранение, а не новый
  алгоритм растеризации или Gaussian splatting.
- Полная / средняя / объёмная детализация переключается явно и одинаково
  для обоих режимов. Автоматического LOD и отсечения зданий пока нет.
- Одинаковые камера, разрешение, материалы, свет, тени и число треугольников
  на одном уровне детализации. Никакой разницы качества ради ускорения B.
- Сравниваем размер **выделенных буферов сцены**, CPU encode/submit,
  интервалы requestAnimationFrame и GPU render passes, если timestamp-query
  доступен. Размер буферов не означает полную VRAM; depth/shadow attachments,
  внутренние аллокации драйвера и browser compositor считаются отдельно.
- Показатель FPS ограничен частотой дисплея. CPU submit не равен времени GPU.
- Автоматическое сравнение фиксирует камеру/сцену, прогревает каждый режим,
  выполняет A/B/B/A, собирает медиану и p95 и экспортирует исходные замеры.
  Уход вкладки в фон или изменение размера окна отменяет сравнение.
- При простое нет постоянного цикла отрисовки. Взаимодействия перерисовывают
  сцену; для измерения есть кнопка сравнения.
- Проверка качества: пиксельное сравнение A/B при фиксированных параметрах.
  Ускорение заранее не обещается: B экономит хранение, но добавляет ALU и
  чтения шаблона в vertex shader.

## Границы первого этапа

Без FBX, fitting, GI, спектральной или волновой оптики. Опыт Юнга — часть
истории идеи, а не реализуемая здесь физическая модель. Свет в прототипе:
направленный diffuse + ambient + shadow map. Материалы не полноценный PBR.

## Запуск

```sh
npm install
npm run dev -- --host 127.0.0.1
npm run build
npm test
```

Нужен браузер с WebGPU; отсутствие API/адаптера выводится в интерфейсе.
GPU timestamps следуют [WebGPU timestampWrites](https://gpuweb.github.io/types/interfaces/GPURenderPassTimestampWrites.html).

## Визуальная система

Опорный концепт: `design/concept.png` (Image Gen, не часть 3D-сцены).
Фон #14191c, панель #1c2327, акцент #b6edce; rail 300 px, header 58 px,
тонкие разделители, системный sans-serif, моноширинные числовые метрики.
На узком экране viewport располагается над панелью. Весь интерфейс — DOM,
вся геометрия — WebGPU. Картинка концепта не используется как фон рендера.

## Выполненные проверки

Проверено 27 сентября 2026 года:

- `npm run build`: TypeScript и production bundle проходят.
- `npm test`: 3 теста — эквивалентность структурного декодирования и A,
  сокращение геометрии при LOD, корректная обработка недоступных GPU-замеров.
- Встроенный браузер: WebGPU, adapter `apple / metal-3`, GPU timestamps.
  Chrome также запустил сцену и завершил сравнение с нулевой разницей пикселей.
- A/B, 16 и 1024 здания, полная/средняя/объёмная детализация,
  отмена прогона, desktop 1536×1024 и узкий viewport 390×844.
- Консоль без ошибок и предупреждений приложения. Страница не пустая,
  Vite overlay отсутствует. При простое счётчик кадров остался 368 → 368.
- Экспорт в Chrome открывает системный диалог «Сохранить» с именем JSON.
  Завершение сохранения через системный диалог не проверено; автоматическое
  ожидание download во встроенном браузере завершилось тайм-аутом.
- Сверены концепт и скриншот через просмотр изображений: компоновка rail,
  подписи и порядок контролов, палитра, иерархия текста, отступы и границы.
  На узком viewport scrollWidth = clientWidth = 390. Намеренные визуальные
  отличия от концепта перечислены в `design/README.md`.

### Контрольное измерение

64 здания, полная детализация, canvas 1236×924, 447 756 треугольников в
основном проходе. Тот же набор дополнительно рисуется в shadow pass.
30 кадров прогрева + 60 измерений на этап; порядок A/B/B/A, 120 измерений
на представление. Камера фиксирована.

| Показатель | A | B |
|---|---:|---:|
| Буферы сцены, байт | 1 791 672 | 33 752 |
| GPU, медиана | 1,376 мс | 1,376 мс |
| GPU, p95 | 1,769 мс | 1,901 мс |
| CPU submit, медиана | 0,200 мс | 0,200 мс |
| Интервал кадра, медиана | 8,3 мс | 8,3 мс |
| Отличающиеся каналы изображения | 0 | 0 |

Буферы B меньше в 53,08 раза. Это не ускорение и не снижение полной VRAM:
для переключения оба варианта одновременно резидентны, shadow texture
занимает ещё 16 МиБ, depth attachment и внутренние аллокации не измерены.
Разницу малых CPU-таймингов не следует переинтерпретировать; timestamps
также ограничены точностью браузера. Результаты относятся только к этому
GPU, ракурсу и процедурной сцене, не являются общим доказательством выигрыша.

Не проверены физические мобильные устройства, Safari/Firefox, реальная
импортированная архитектура, автоматический LOD и длительные стресс-тесты.
