# NuRender: GitHub Pages + Yandex Object Storage

Код и интерфейс собираются в GitHub Pages. Модель, текстуры и окружение находятся в отдельном
версионном каталоге Object Storage; `.blend` в публикацию не входит.

В `.env.pages` задан адрес подготовленного выпуска:
`https://storage.yandexcloud.net/maragojeep/nurender/assets/v0.14.0/`.
Это публичная конфигурация, не секрет.

## Сборка приложения

```sh
npm ci
npm run test:unit
npm run build:pages
node scripts/check-pages.mjs
npm run preview:pages
```

Открывать preview по `/NuRender/`. Pages-сборка не копирует `public/`. По умолчанию она
открывает полную сцену в мобильном профиле с потоковой геометрией (`stream`). Облегчённый
обзор приблизительный; `?geometry=legacy` возвращает обычную мобильную геометрию,
а `?profile=desktop` включает исходную детализацию. Локальная dev-сборка сохраняет
прежний выбор профиля по устройству и обычную геометрию по умолчанию.

Workflow `.github/workflows/pages.yml` публикует `dist/` при push в `main`.
Для нового репозитория `NieMandX/NuRender` требуется выбрать **Settings → Pages → GitHub Actions**.
Если имя репозитория меняется, обновить `base` в `vite.config.ts` и проверку пути.

`npm run test:unit` не требует моделей: проверки локальных файлов и их интеграционные группы
пропускаются явно, включая подготовку файлов до запуска тестов.
`npm test` проверяет также реальные экспорты и их хеши и требует ресурсов под `public/`.
Полноценный рендер нужно проверять отдельно в браузере с WebGPU; CI это не заменяет.

## Ресурсы

Подготовка копий с gzip не изменяет исходные файлы:

```sh
python3 scripts/package-assets.py --out /tmp/nurender-assets-v0.14.0
```

Имена сохраняются (`scene.json`, `.bin`, `.png`), тело каждого объекта сжато. При загрузке
обязателен `Content-Encoding: gzip`; браузер распакует ответ перед JSON, meshopt и SHA-256.
Также задаётся `Cache-Control: public,max-age=31536000,immutable`. Тип содержимого определяется
по исходному расширению. Новые ресурсы публикуются в новом каталоге версии, старые не перезаписываются.
Нельзя синхронизировать корень бакета с `--delete`.

Предыдущий подготовленный набор 0.12: 4345 исходных файлов, **1 601 683 214 байт → 514 041 527 байт gzip**
без дополнительного индексного manifest. Посетитель скачивает только выбранный профиль:
мобильная папка — около 81.3 МБ gzip, полный профиль — 393.8 МБ, фрагмент — 34.9 МБ;
окружение добавляет около 4.1 МБ. Не все карты профиля обязательно запрашиваются.
Это размер передачи, не GPU-память. Набор 0.14: **15 743 файла, 2 000 640 870 байт →
754 729 109 байт gzip**, без дополнительного индексного manifest. Он дополнительно
содержит `m8-paged` и `m8-stream`. Режимы `geometry=paged` и
`geometry=stream` в мобильном профиле загружают свою базу и необходимые подробности;
изображения берут из `m8-mobile`.

Существующий CORS бакета `maragojeep` разрешает GET из браузера. Доступ к самим объектам
проверяется отдельно: публичный статичный сайт требует публичных объектов либо авторизованного
сервиса выдачи URL. Ключи Object Storage нельзя помещать в `.env.pages`, JavaScript или workflow.
Для локальной загрузки используется уже настроенный AWS CLI profile `yc-s3`.

После публикации проверить анонимный GET с Origin сайта, CORS, Content-Encoding, распаковку
и SHA-256, затем сам Pages-сайт с холодным кэшем: версия 0.14, полная модель, PBR, переключение
профиля, материалы, тени и отсутствие ошибок GPU. Проверить реальные телефоны отдельно.
