# NuRender / Structured Renderer 0.9

Локальный исследовательский стенд на прямом WebGPU / WGSL, без Three.js и Babylon.js.
Сравнивает стоимость трёх представлений одной сцены. Текущая версия переносит
из Blender UV, цветовые и PBR-карты и добавляет HDR-освещение.
Растеризация, инстансинг, GGX и HDRI — стандартные методы; новизна представления
геометрии остаётся исследовательской гипотезой, а не доказанным преимуществом.

## Запуск

```sh
npm install
npm run dev -- --host 127.0.0.1
npm run build
npm test
```

Текущий адрес: `http://127.0.0.1:5174/?scene=blender`.
WebGPU обязателен. ЛКМ — вращение, колесо — масштаб, 1/2/3 — режим.
Рендер работает по событию; постоянный цикл запускается только для измерений.

## Материалы и UV

Из открытого `M8_new_PBR_flow.blend` прочитаны 38 материалов, 20 с подключёнными
картами, и 34 уникальных упакованных изображения 1024×1024. Исходная сцена Blender
не менялась. Повторный экспорт выполнен во временный каталог; все vertex/index
буферы и записи групп совпали побайтно с прежним экспортом. В проект добавлены
только `textures.json`, 39 файлов координат и изображения; sourceDigest прежний.

Экспортёр сохраняет UV на каждом углу треугольника, включая интерполяцию на
границе обрезки. При загрузке разделяются вершины на UV-швах. Для каждого
повторяющегося элемента B сохраняются его собственные UV и ID материала;
общая форма не подменяет координаты текстуры остальных копий. Каноническое
сопоставление учитывает перестановку треугольников и циклическую перестановку углов.

Переносятся:

- Base Color с флагом sRGB/Non-Color исходного изображения.
- Roughness и Metallic, включая зелёный/синий каналы ORM.
- Tangent Normal Map с исходной силой; базис восстанавливается по исходной UV-развёртке.
- Масштаб, поворот, смещение Mapping. Для режима Texture используется обратная
  матрица, для Point — прямая; V переворачивается один раз при выборке.
  [Семантика Blender Mapping](https://docs.blender.org/manual/en/latest/render/shader_nodes/utilities/vector/mapping.html).
- Mip-цепочки, линейное усреднение цветовых изображений с учётом sRGB,
  трилинейная фильтрация и анизотропия 4×. Данные normal/ORM не декодируются как sRGB.

Панель «Текстуры из Blender» переключает три режима: без карт, только цвет,
цвет + PBR-карты. В последнем также используются исходные константы roughness/metallic.
В текущем экспорте нет неподдержанных подключений (`warnings: []`).

Поддержан один активный render UV-слой, плоские повторяющиеся Image Texture,
Mapping и подключённые к Principled BSDF перечисленные карты. Это не универсальный
интерпретатор Blender nodes: сложные смеси, процедурные графы, displacement, AO,
alpha-карты и произвольные UV-слои не перенесены. Нормали восстанавливаются из
производных треугольника; точное совпадение с MikkTSpace/Blender не заявляется.

## Правила распознавания

Имена материалов, объектов и групп классифицируются совместно. Конкретное
название стемолита имеет приоритет над общим Glass/стекло, в том числе между
разными именами. Варианты «стемолит», «стемалит», «стимолит» распознаются.

- Стемолит всегда светлый, непрозрачный и глянцевый: roughness 0.08, metallic 0.
  Исходные карты не перекрашивают его и не делают прозрачным.
- Стекло прозрачно, roughness 0.08, metallic 0.
- Металл/названия металлов задают metallic 1; карты цвета и шероховатости сохраняются.
- Ручной материал B заменяет карты выбранной копии/семейства. Сброс возвращает
  автоматические назначения и исходные карты. Файлы `.numat.json` версий 0.7/0.8
  совместимы: идентичность геометрии и порядок элементов сохранены.

В M8: 1 группа стекла, 1 стемолита, 10 групп с металлами. По буквальному правилу
пользователя `Paint - Titanium White` также считается металлом. `Golden Beige`
не содержит самостоятельного названия gold. Подробности распознавания видны в UI.

Стекло использует weighted blended OIT: accumulation RGBA16F + revealage R8 и
композицию. Нет преломления, цветного поглощения, теней стекла или отражения
самой геометрии сцены. Стемолит пишет глубину и отбрасывает обычную тень.
В 0.9 также исправлено накопление прозрачного цвета: RGB умножается на alpha
до применения веса, иначе после нормализации стекло становилось слишком ярким.
Композиция прозрачности пока выполняется после tone mapping.

## HDR-окружение

В проект включена исходная 1K Radiance RGBE-панорама
[Urban Courtyard 02](https://polyhaven.com/a/urban_courtyard_02), Sergej Majboroda /
Poly Haven, [CC0](https://polyhaven.com/license). Браузер загружает локальный файл;
обращения к стороннему сервису при работе рендера нет.

Собственный ограниченный RGBE-декодер проверяет SHA-256, формат и границы RLE,
сохраняет значения выше 1 и загружает RGBA16F с mip-цепочкой. Рассеянное освещение
приближено девятью коэффициентами сферических гармоник
([описание SH](https://www.ppsloan.org/publications/StupidSH36.pdf)).
Зеркальная часть использует 16 фиксированных GGX importance samples; уровень mip
учитывает плотность выборки. Это приближение: возможны шум/изменение бликов при
движении камеры, особенно у ярких деталей панорамы. Это не GI и не отражения
локальных объектов. Прямой направленный свет с shadow map остаётся отдельным
художественным источником, не калиброванным по солнцу HDRI.

Окружение можно повернуть на 0–360° либо вернуть процедурное. HDRI освещает
материалы, фон canvas остаётся нейтральным. Экспозиция/поворот Blender World
не копируются: в исходной сцене HDR-карты мира не было.

## Три представления и память

- A: отдельные исходные объекты.
- C: обычный инстансинг общей геометрии объектов.
- B: 222 семейства / 2624 повторяющиеся части, пакетная адресация общей геометрии
  и отдельных атрибутов экземпляра плюс уникальные остатки. Все 675408 треугольников
  присутствуют во всех режимах; 67 исходных объектов.

Пакет B добавляет таблицы UV и их смещений на элемент. Количество команд остаётся
40 на проход. В резервном режиме «По шаблону» копии с разными UV рисуются отдельно;
он служит проверкой корректности и не является прежним бенчмарком инстансинга 0.8.

| Выделение | Байты |
|---|---:|
| Буферы A/C | 22 658 736 |
| Буферы пакетного B | 20 049 664 |
| Все residentSceneBuffers стенда | 40 247 296 |
| Сохраняемые CPU typed arrays реальной сцены | 30 561 124 |
| Материальные изображения, mip-цепочки и таблица | 190 148 600 |
| HDRI, mip-цепочка и SH | 5 592 552 |

Переключатель карт не выгружает изображения. Текстуры пока несжатые; около
181.34 МиБ занимают материалы отдельно от геометрии. Это заметная стоимость
данного этапа. Числа — явные выделения, не полная VRAM: shadow/depth/OIT,
драйвер, временные upload-ресурсы, JS-объекты и данные подготовки учитываются отдельно.
Стенд одновременно хранит альтернативные представления и процедурную сцену.

## Проверка 0.9 от 27.09.2026

32 теста, `npm run build`. Проверены UV-швы, разные координаты/ID материалов у
копий, GPU-адресация, контрольные суммы, RGBE RLE, интегрирование постоянного
освещения в SH, прежняя геометрия, диагностика, восстановление материалов и
совместимость сохранённых пакетов. WebGPU проверен во встроенном браузере на
Apple metal-3; другие GPU и физические мобильные устройства не проверялись.

Контрольный общий вид, canvas 1140×900, полный PBR + HDRI. A/B/C/C/B/A,
30 кадров прогрева и 60 измерений на этап; 120 выборок на режим.

| Метрика | A | B пакетный | C |
|---|---:|---:|---:|
| GPU median, мс | 10.813 | 10.617 | 11.141 |
| GPU p95, мс | 14.877 | 13.959 | 13.435 |
| CPU submit median, мс | 0.200 | 0.300 | 0.300 |
| Draw calls, все проходы | 202 | 121 | 118 |
| Отличающиеся от A пиксели | — | 153 / 1 026 000 | 0 |

B/A: max delta 233/255, MAE 0.004007/255. Разница мала по площади, но не по
максимальной ошибке отдельного пикселя. Меняются порядок треугольников и
float32-арифметика, в исходнике есть перекрывающиеся поверхности. Причина каждого
отличающегося пикселя отдельно не изолирована. Ускорение B относительно C не доказано.

GPU-время — сумма shadow, opaque, transparency и composite passes. CPU submit
не измеряет исполнение GPU; RAF/FPS включает планирование браузера и ожидания.
JSON сохраняет режим карт, источник/поворот окружения, камеру, размеры, все выборки,
метрики и попиксельное сравнение. Замеры отключены при диагностике или ручных
назначениях, чтобы не сравнивать разные материалы.

На крупном плане фасада (#213), те же 1140×900: GPU median A/B/C =
14.811 / 16.515 / 15.008 мс. B/A отличается на 1050 пикселях (0.102%),
max delta 169/255, MAE 0.019297/255; C/A совпадает. Полные выборки сохранены в
`docs/benchmarks/0.9-overview.json` и `docs/benchmarks/0.9-facade.json`.

В браузере также проверены три режима карт, поворот/смена окружения,
ручное назначение одной копии и сброс, резервный путь B, переключение на
процедурную сцену A/B/C и обратно, viewport 390×844 без горизонтального скролла.
Ошибок/предупреждений приложения и WebGPU не обнаружено.
