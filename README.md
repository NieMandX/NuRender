# NuRender / Structured Renderer 0.12

Локальный исследовательский стенд на прямом WebGPU / WGSL, без Three.js и Babylon.js.
Профиль полного качества открывает всю видимую геометрию `M8_new_PBR_flow.blend`:
**265 объектов и 16 988 989 треугольников**, без обрезки и упрощения.
Исходный файл и состояние объектов в Blender не менялись.
В 0.11 добавлены кэш статичных теней, подготовленные HDR-отражения и мобильный профиль.
В 0.12 — отдельная Pages-сборка с ресурсами в Яндекс Storage, ограниченная параллельная
загрузка частей и переключаемое отсечение геометрии вне кадра.

Публикация подготовлена, но ещё не завершена: ожидаются вход в GitHub и подтверждение
публичного доступа к экспортам модели. Настройка — [hosting.md](docs/hosting.md).
Исследование свежих алгоритмов и следующий шаг — [обзор 2023–2026](docs/rendering-research-2026-09-28.md).

## Запуск

```sh
npm ci
npm run dev -- --host 127.0.0.1 --port 5174
npm run build
npm test
```

- [Полная M8](http://127.0.0.1:5174/?scene=full&profile=desktop).
- [Мобильная M8](http://127.0.0.1:5174/?scene=full&profile=mobile).
- [Прежний фрагмент M8](http://127.0.0.1:5174/?scene=blender).
- [Процедурный стенд](http://127.0.0.1:5174/).

Модели исключены из Git. Для локальных импортированных сцен нужны экспорты в `public/`,
либо `VITE_ASSET_BASE` с корнем опубликованных ресурсов в `.env.local`.
Для проверки кода без файлов модели: `npm run test:unit`.

WebGPU обязателен. Мышь или палец — вращение, колесо или два пальца — масштаб, 1/2/3 — режим.
Мобильный профиль выбирается автоматически для Android/iPhone/iPad, включая iPad с desktop User-Agent;
явный `?profile=mobile` или `?profile=desktop` имеет приоритет. Переключатель профиля перезагружает сцену.
На телефоне нужен HTTPS-адрес: `127.0.0.1` относится к самому телефону, а обычный HTTP по LAN
не даёт безопасного контекста WebGPU. Наличие WebGPU проверяется при запуске; WebGL fallback отсутствует.
Рендер работает по событию; постоянный цикл запускается только для измерений.
В полном профиле смена источника сохраняет сцены в памяти. В мобильном предыдущая импортированная
сцена освобождается перед новой загрузкой, чтобы не складывать их расход памяти.

## Что сравниваем

| Представление | Полная сцена | Фрагмент |
|---|---|---|
| A | Части исходных объектов, отдельные вызовы | Исходные объекты |
| C | Инстансинг частей общих мешей | Инстансинг общих мешей |
| B | Пакеты исходных частей с адресацией вершины и элемента | Найденные внутри мешей повторяющиеся детали, общие шаблоны и уникальные остатки |

В полном профиле во всех представлениях остаются все 16 988 989 треугольников.
В мобильном A/B/C используют общую упрощённую геометрию; B меняет материалы через
инстансы, без дополнительного массива адресов vertex pulling.
**Поиск внутренних геометрических повторов на полную сцену ещё не перенесён.**
Его прежняя проверка доступна во фрагменте: 67 объектов, 675 408 треугольников,
222 найденных семейства / 2624 повторяющиеся части. 220 групп материалов полной
сцены — исходные сочетания меша и материала, а не найденные геометрические шаблоны.
Растеризация, пакетирование, инстансинг, GGX и HDRI — стандартные методы.
Преимущество структурного представления остаётся исследовательской гипотезой.

## Загрузка полной модели

`scripts/export_blender_full.py` читает открытый Blender-файл без операторов,
сохранения, изменения выделения или геометрии. Вызов `start()` экспортирует
небольшими шагами через Blender timer. Экспортёр останавливается при активных
модификаторах: в проверенной M8 их нет. Сохраняет активный render UV-слой,
исходные float32-позиции, плоские нормали и общие данные связанных мешей.
Поддержка сглаженных нормалей Blender остаётся отдельным этапом.

`public/scenes/m8-full/` содержит 962 части и 1 294 003 996 байт геометрии.
Часть ограничена 60 000 вершинами до объединения одинаковых записей; UV-швы
сохраняются. Каждая вершина — позиция, нормаль и UV, 32 байта.
SHA-256 каждого vertex/index-файла проверяется перед загрузкой, затем CPU-геометрия
освобождается. Браузер собирает 781 ограниченный пакет вместо одного гигантского
storage buffer. Вершины общие для A/B/C; индексные буферы A/C и адреса B отдельные.
Старшие 16 бит адреса B — элемент, младшие — вершина внутри пакета.

Ручной материал B применяется ко всем частям выбранного объекта/материала или
одной его копии. A/C сохраняют исходные автоматические назначения для сравнения.
Автосохранение и `.numat.json` привязаны к идентичности конкретного экспорта;
пакеты фрагмента, полного и мобильного экспорта не смешиваются. Сброс возвращает исходные карты.

## Материалы и освещение

В полной M8 прочитаны 162 исходных материала и 127 изображений. Три записи
добавлены для вариантов с недоступными UV-картами: всего 165 записей,
97 с поддержанными подключениями карт.

Для первого прогона полной сцены текстуры загружаются в **512×512**.
Оригиналы 1024×1024 сохранены локально; фрагмент использует 1024×1024.
Уменьшение цветовых карт и mip-цепочки выполняются в линейном пространстве
с учётом sRGB. Normal/ORM остаются линейными; трилинейная фильтрация, анизотропия 4×.

Переносятся Base Color, Roughness, Metallic и Tangent Normal, каналы ORM,
масштаб/поворот/смещение Mapping. Режимы: без карт, только цвет, цвет + PBR.
Это ограниченный перенос Principled/Image Texture, а не интерпретатор Blender
nodes: процедурные смеси, displacement, alpha-карты и произвольные UV-слои
не поддержаны. Базис normal map восстанавливается из UV; точное совпадение
с MikkTSpace/Blender не заявляется.

В исходнике отсутствуют UV-слои, указанные в следующих подключениях:

| Материал | Отключённые карты | Отсутствующий UV-слой |
|---|---|---|
| Metal - Iron | Цвет | M8_Iron_EN_Base_UV |
| Мощение - Камень Серый | Цвет, шероховатость, металличность, нормали | M8_Stone_PBR_UV |
| Металл - Железо | Цвет | M8_Iron_Base_UV |

Используются постоянные параметры этих материалов; остальные поддержанные карты
работают. Шесть исключений перечислены в панели «Карты с ограничениями».

Имена материалов, объектов и групп классифицируются совместно:

- Стемолит/стемалит/стимолит имеет приоритет над общим Glass/стекло: светлый,
  непрозрачный, глянцевый; roughness 0.08, metallic 0. Исходные карты не перекрашивают его.
- Стекло прозрачно; roughness 0.08, metallic 0.
- Металл и названия металлов задают metallic 1, сохраняя цвет/шероховатость карт.
- Неизвестные имена сохраняют исходные параметры; ручные назначения имеют приоритет.

В полной сцене распознано 21 группа стекла, 5 стемолита, 45 металла.
Стекло использует weighted blended OIT; без преломления, цветного поглощения
и теней стекла. Композиция прозрачности пока выполняется после tone mapping.

HDRI: [Urban Courtyard 02](https://polyhaven.com/a/urban_courtyard_02),
Sergej Majboroda / Poly Haven, [CC0](https://polyhaven.com/license), локальный 1K RGBE-файл.
Собственный декодер, RGBA16F mip-цепочка, 9 SH-коэффициентов для рассеянного света,
GGX cubemap 256² с 9 уровнями шероховатости и BRDF LUT 128² для зеркального света.
Сложная интеграция перенесена в подготовку ассетов: 1024 выборки на texel куба, 2048 для LUT.
Дополнительные GPU-текстуры занимают 4 325 360 байт. Контрольный режим с прежними
16 GGX-выборками доступен в меню «Отражения HDR». Split-sum — приближение, его изображение
не обязано совпадать с прежней шумной оценкой из 16 выборок. Окружение вращается;
доступен процедурный вариант. Фон нейтральный. Прямой свет с shadow map отдельный,
не калиброван по солнцу HDRI. Нет GI и отражений локальных объектов;
возможен шум бликов. Подробности этапа материалов: [0.9](docs/stage-09.md).

## Статичные тени

Shadow map строится при первом кадре и изменении источника, представления, геометрии,
области света, диагностической окраски или набора ручных материалов, влияющего на отбрасывание теней.
Вращение, масштаб камеры, смена PBR-карт и поворот окружения её не перестраивают.
Изменение геометрии в будущем обязано обновлять `sceneRevision`.
Карта света охватывает сцену, не следует за камерой; приближение камеры не добавляет разрешения тени.
В полном профиле размер 2048², в мобильном 1024². GI, lightmaps и PCSS пока не реализованы.

Бенчмарк считает GPU-время отдельно для shadow / opaque / glass / composite. Шесть холодных
кадров с принудительным построением сохраняются отдельно в `coldSamples`; после прогрева
измеряются кадры с готовой тенью. `shadowQuality` проверяет кэш против принудительного построения.
Таймстемпы пропущенного прохода равны нулю, оставшиеся значения старого кадра не учитываются.

## Мобильные ассеты

Все 265 объектов и 962 исходные части сохранены. **9 125 832 треугольника** вместо 16 988 989.
Это отдельная версия с потерей детализации: meshoptimizer 1.3.0, attribute-aware simplification,
Permissive + LockBorder, без удаления компонентов. Цель 15% треугольников не достигнута
из-за ограничений качества; фактически осталось 53.7%. Предел ошибки алгоритма 0.005 относителен
масштабу части и не является гарантией пиксельной или метрической точности всей модели.
Если упрощение обнуляет часть, сохраняются её исходные треугольники.

Позиции квантованы в локальном AABB части (`unorm16x4`), нормали — `snorm8x4`, UV — float32x2.
20 байт на вершину; одинаковые записи объединены, UV-швы сохранены. Декодирование позиции
встроено в матрицу инстанса, исходная матрица нормалей сохранена. Дополнительная погрешность
только квантования позиции ограничена 0.00812 единицы сцены; это не учитывает ошибку упрощения.
Индексы uint16. Meshopt сжимает передачу без дополнительных потерь после квантования.
Сетевые запросы перекрываются: до трёх частей в мобильном профиле и четырёх в полном
плюс текущая декодируемая часть. В каждой части параллельно запрашиваются вершины и индексы.
Декодирование и GPU-upload сохраняют исходный порядок; при ошибке оставшиеся запросы отменяются.
Полный CPU-массив всей сцены не собирается.

| Ресурс мобильной M8 | Байты |
|---|---:|
| Геометрия при передаче | 130 979 029 |
| Распакованные вершины + индексы, без выравнивания | 354 926 564 |
| Все GPU-буферы загруженной полной сцены | 355 246 668 |
| Текстуры при передаче | 11 003 357 |
| GPU-карты 256² с mip-уровнями и таблицей материалов | 44 418 764 |

Размер GPU-буферов не равен всей памяти процесса или VRAM. Дополнительно нужны небольшая
процедурная сцена, HDR, framebuffer/depth/OIT, временные ресурсы браузера и драйвера.
DPR ограничен 1, canvas — миллионом пикселей. При неподвижной сцене новые кадры не запрашиваются.
Сильно приближённый вид в мобильном профиле теряет детали; полное качество доступно отдельно.

Повторная подготовка (Node.js; для Python — NumPy и Pillow):

```sh
node scripts/prepare-mobile-scene.mjs
python3 scripts/prepare-mobile-textures.py
python3 scripts/prefilter_ibl.py
```

Исходные `m8-full` и HDR-файлы остаются неизменными. После повторного экспорта полной модели
нужно выполнить обе команды мобильной подготовки; первый шаг обновляет её manifest, второй — карты.
`meshoptimizer` используется как кодек и офлайн-упрощатель, рендер остаётся собственным WebGPU/WGSL.

## Проверка 27.09.2026

`npm run build` и `npm test` прошли: **42 теста**. Проверяются обе геометрии и хеши, декодирование mobile meshopt,
границы памяти частей, сохранность UV/матриц/объектов, ручные назначения A/B/C,
очистка при ошибке загрузки, обнаружение iPad, ограничение пикселей, конечность HDR/LUT,
ориентация всех граней cubemap, учёт пропущенных GPU-проходов.

Контрольный настольный GPU — Apple metal-3, полный PBR и HDR, canvas 1140×900,
A/B/C/C/B/A, 30 прогревочных + 60 измеряемых кадров на этап, 120 выборок на режим.

| Вариант полного качества | A median, мс | B median, мс | C median, мс |
|---|---:|---:|---:|
| 0.10, тени каждый кадр, 16 GGX-выборок | 39.191 | 37.487 | 38.535 |
| 0.11, только кэш теней | 34.013 | 32.113 | 33.751 |
| 0.11, кэш + подготовленные отражения | 15.729 | 13.566 | 15.335 |

В этих прогонах B: на 14% меньше GPU-времени только от кэша, на 64% — вместе с подготовленным IBL.
Это сравнение версий нашего движка на одном GPU и одном ракурсе, не сравнение с Three.js/Babylon.js.
A/B/C совпали пиксельно внутри каждого способа освещения. Кэш и заново построенные тени совпали.
GPU-время — сумма проходов; RAF также включает vsync, планирование и ожидание readback.
Результат не гарантирует такое же ускорение на другом GPU. Исходная проверка 0.10: [история](docs/stage-10.md).

Мобильный профиль на том же настольном GPU: B median 9.306 мс, canvas 1125×888,
с упрощённой геометрией, картами 256 px и тенью 1024². Это другая настройка качества,
поэтому её нельзя выдавать за ускорение при одинаковом изображении или за FPS телефона.
A/B/C и кэш теней внутри мобильного профиля совпали пиксельно.

В браузере проверены ширина 390 px без горизонтального скролла, pinch/вращение/отмена касания
через touch events Chrome, назначение и сброс материала, переход полная → фрагмент → полная
с нулевым кэшем предыдущей сцены. При движении камеры счётчик построений тени не растёт.
Ошибок WebGPU/приложения не обнаружено.

Физические телефоны и планшеты пока не проверены. Мобильный профиль и узкий viewport в
настольном браузере проверяют код и интерфейс, но не мобильную память, нагрев или устойчивость Safari.

## Проверка 0.12 — 28.09.2026

Все **49 тестов** с локальными экспортами проходят. В отдельной чистой копии без `public/`
проходят 32 проверки кода, 12 проверок/групп ресурсов явно пропускаются; Pages-сборка и проверка
пути `/NuRender/` проходят. Размер приложения — около 210 КБ без моделей.
Тесты дополнены обработкой временных сетевых ошибок: GET повторяется до двух раз, 404 не
повторяется, отмена немедленно прерывает ожидание. После исчерпания повторов ошибка содержит URL.

Сборка проверена через два локальных HTTP-origin: интерфейс на пути `/NuRender/`, модель на
отдельном сервере с CORS и `Content-Encoding: gzip`. Открылись мобильная и исходная полная M8,
включая HDR и PBR. Это проверка схемы доставки; сам GitHub Pages и облачный endpoint ещё не опубликованы.

На близком ракурсе мобильного профиля frustum culling пропускает 746 из 1110 частей с учётом
копий, B сокращается с 963 до 323 draw calls. В A/B/C вывод с отсечением совпал пиксельно
с полным выводом; кэш теней совпал с перестроением. В полном профиле те же проверки тоже прошли.
Сохраняются все отбрасыватели теней, включая находящиеся за камерой.

После кэширования видимости при неподвижной камере CPU median B — 1.0 мс в обоих вариантах.
GPU median B в мобильном профиле — 8.52 мс с отсечением против 8.65 мс без него; предыдущая
пара прогонов не показала выигрыша. **Устойчивое ускорение GPU мобильного профиля пока не подтверждено**:
уменьшение draw calls само по себе недостаточно. Это Apple metal-3, canvas 1125×888,
yaw 0.72, pitch 0.68, distance 35.368; не измерение телефона.

В исходном полном профиле на том же близком ракурсе, canvas 1140×900, эффект значительнее:
B median **13.369 мс без отсечения → 7.864 мс с отсечением**, повторный проход с отсечением —
7.733 мс. Это примерно 41–42% меньше GPU-времени в этих замерах. Draw calls B: 796 → 258;
CPU median: 0.5 → 0.4 мс. A/B/C, кэш теней и включение/выключение отсечения совпали пиксельно.
Результат зависит от ракурса: на общем виде, где вся модель в кадре, отсекать нечего.

Ограничения: видимость считается по AABB, крупные частично видимые пакеты рисуются целиком;
нет occlusion culling, потокового LOD или выгрузки невидимых частей из GPU. При новом перемещении
геометрии потребуется также обновлять границы и сбрасывать кэш видимости.
